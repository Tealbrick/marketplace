# Formbricks provenance

- App: Formbricks 6.0.2 (`ghcr.io/formbricks/formbricks:6.0.2`, upstream latest). Captured 2026-10-06. The instance serves no spec endpoint, so the upstream docs specs at tag `6.0.2` are used.
- Vendored `openapi.json` merges the four upstream documents (sha256 of each upstream file below). Paths carry their full `/api` prefix (v2 and the legacy root were relative to `/api/v2` and `/api`), components are namespaced `v1_`, `v2_`, `v3_`, `root_` so same-named schemas cannot collide, every operation gets a generation tag (`api-v1`, `api-v2`, `api-v3`, `legacy-root`) and a `[API vN]` summary prefix, and the legacy root operation ids are prefixed `legacyRoot`. v2 operations without their own `security` inherit the document-level `apiKeyAuth`. Nothing else is changed, so the upstream operations are untouched. Vendored sha256 `2a9166ffe36bdd669fd4bee60647c759ad2be185536c3981de135b35edc71d44`. The engine drops the 26 v1 `x-api-key` header parameters and tolerates the undeclared `workspaceId` path parameter of v1 `PUT /api/v1/client/{workspaceId}/responses/{responseId}` by itself. `overlay.json` (pinned in `entry.json`, sha256 `5cf9d53fb8dc51328508576d1149954b003f43985f092b8d3064b46bbd9d37b3`) holds one fix: v1 `GET /api/v1/management/surveys/{surveyId}/singleUseIds` uses OpenAPI 3.0 boolean `exclusiveMinimum`/`exclusiveMaximum` on its `limit` parameter, which is invalid in the 3.1 dialect and fails argument validation, so those two keywords are removed.

- Decision: the generations are different resources of one product, not copies. v1 holds survey, action class, contact read, storage and single-use link management, v2 holds responses, contacts, webhooks, teams, users and roles, v3 holds surveys, workflows, tags and feedback records. Overlaps (responses, webhooks, contact attribute keys, health, client API) are all still current in 6.0.2, so all of v1, v2 and v3 are exposed. Only the legacy root document (`/api/responses`, same five operations and ids as v2 `/management/responses`) is fully superseded; each of its five operations is excluded with its own reason naming the v2 successor.
- Operations: 113 total, 108 exposed, 5 excluded. Exposure: above the 64-operation limit, so `auto` selects discovery.
- Outward (25, held for approval): survey create/update that can publish (v1, v3), response writes that run webhooks and notification pipelines (management and client, v1 and v2), public file upload, webhook create/update, user invite and role change, team and workspace-team writes, workflow enable. Destructive beyond DELETE: tag merge.
- Reads (3, `connector.observe`): `validateSurveyV3` (`POST /api/v3/surveys/validate`, documented as validating a payload without writing data), `testWorkflowV3` (`POST /api/v3/workflows/{workflowId}/test`, documented as a validation with no run, email or webhook, so it moved from outward to reads) and `searchFeedbackRecordsV3` (`POST /api/v3/feedbackRecords/search/semantic`, an embedding search returning ids and scores). Not a read: `generateSurveyV3` (sends the prompt to an AI provider).
- Auth: `x-api-key: <key>` (Organization settings > API Keys; choose workspace access read/write/manage). The public client API ignores it. Feedback-record operations need the Enterprise licence.
- Base URL at install: the app origin (`WEBAPP_URL`). Deployed on the `neuu` node behind tailscale serve: `https://neuu.<tailnet>.ts.net:8511`.
- Health: `GET /api/v2/me` (`me`; it verifies the API key, unlike the public health check).
