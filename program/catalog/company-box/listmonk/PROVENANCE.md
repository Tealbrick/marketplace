# Listmonk provenance

- App: listmonk 6.2.0 (high confidence: the instance's login page assets and `/robots.txt` match v6.2.0 and differ from v6.1.0 and earlier; not verified with an authenticated call). Captured 2026-10-06.
- Upstream: `knadh/listmonk` tag `v6.2.0`, commit `ef0a75872463f10a4848af6c547d1c057405453a`.
- Vendored `openapi.json` is the generated complete spec from the Company Box research (`specs-full/listmonk-6.2.0.openapi.json`, generator `gen_listmonk.py`), sha256 `a60f2ccff80a50b73bf9e2c139b62e1e24d9131c2ce000ed53a1ccfa416e6228`. It combines the upstream swagger (`docs/swagger/collections.yaml`, 72 operations) with the 35 router routes the swagger omits (users, roles, settings keys, profile, 2FA, subscriber activity and PATCH, exports, maintenance). The router has 107 `/api`, `/webhooks` and `/health` registrations and the spec covers all of them.
- Operations: 107 (GET 42, POST 24, PUT 21, DELETE 19, PATCH 1). Exposed 104, excluded 3: `GET /api/events` (endless SSE stream), `POST /api/logout` (browser session cookie only) and `GET /api/templates/{id}/preview` (the upstream swagger declares a form body on a GET, which HTTP clients cannot send; `POST /api/templates/preview` covers it).
- Outward from `x-outward` (9): campaign status change, test sends, `/api/tx`, opt-in emails (subscriber create/update/patch/optin, public subscription), SMTP test. Destructive beyond DELETE from `x-destructive` (12): bulk blocklist and list changes, settings writes, admin reload, campaign status, subscriber query delete. All 19 DELETEs are destructive by method.
- Auth: HTTP Basic with the API user name and its token as password (`curl -u api_user:token`). Chosen over `Authorization: token <user>:<token>` because the install form then keeps the user name and the secret in separate fields and only the token is treated as a secret. Create the API user under Users with a role limited to what the agent needs.
- Base URL at install: the app origin (the spec paths already carry `/api`; `basePath` is set to empty). Deployed on the Postiz/Listmonk VM behind tailscale serve: `https://fedora-n150.<tailnet>.ts.net:8477`.
- Health: `GET /api/about` (authenticated, returns the deployed version).
