# Nextcloud provenance

- App: Nextcloud server 31.0.14 (instance `status.php`: 31.0.14.1, the neuu instance). Captured 2026-10-06.
- Enabled apps were read on the instance with the read-only `occ app:list --output=json`. 49 apps are enabled, 6 are disabled (`admin_audit`, `encryption`, `suspicious_login`, `twofactor_nextcloud_notification`, `twofactor_totp`, `user_ldap`). Disabled apps are not merged (`user_ldap` ships an OpenAPI document, 4 operations, deliberately left out).
- Vendored `openapi.json` is **merged, not edited**: every enabled app's published OpenAPI document plus three hand-authored documents merged into one OpenAPI 3.0.3 document (`info.x-source: merged-upstream`, `info.x-hand-authored-apps`), by a deterministic script (apps sorted by name). Per app: component schemas are renamed `<app>.<Name>` and their `$ref`s rewritten; every operation gets `x-nextcloud-app: <app>` and tags `[<app>, <app>/<original tag>...]`, so the Portal group is the app. One `operationId` collided (`preview-get-preview` in core, files_trashbin and files_versions); the later two became `files_trashbin-preview-get-preview` and `files_versions-preview-get-preview`. No path+method collided. sha256 in `entry.json`. The merge script, build driver and the generator of the hand-authored documents are kept in the research workspace (`/Users/puma/work/scratch/nextcloud-merge/`: `merge-ocs.mjs`, `build.sh`, `gen-handauthored.py`); inputs below. The generated hand-authored documents are in `sources/`.
- Server-bundled sources, `nextcloud/server` tag `v31.0.14` (commit `aec70613fe00fb9bbeec2c5e6726fc3353333ce2`), the `-full` variant where one exists (all scopes), else `openapi.json`: `core/openapi-full.json` (77 ops, sha256 `d9bf66f7eaa0...`), `apps/{cloud_federation_api 2, dashboard 7, dav 6, federatedfilesharing 9, files 16, files_external 1, files_reminders 3, files_sharing 23, files_trashbin 1, files_versions 1, oauth2 2, theming 11, updatenotification 2, user_status 10, weather_status 7, webhook_listeners 6}/openapi.json`, `apps/{federation 7, provisioning_api 43, settings 3}/openapi-full.json`.
- Non-bundled sources (apps shipped with the 31.0.14 release image, installed versions from `occ`), tags `v31.0.14`: `nextcloud/notifications` (installed 4.0.0, `openapi-full.json`, 12 ops, commit `e5370622bb59`), `nextcloud/recommendations` (4.0.0, 2 ops, `c39a2918beab`), `nextcloud/password_policy` (3.0.0, 2 ops, `3a8c9407aa64`); `nextcloud/user_oidc` tag `v8.7.0` (installed 8.7.0, 9 ops, commit `9f13fd44da4e`). Source file sha256 prefixes: notifications `d231fddde522`, password_policy `65e789b3c938`, recommendations `965c3690e4b6`, user_oidc `f4b2db5dc86b`.
- Upstream OCS operations: 262 over 24 apps (core 77, provisioning_api 43, files_sharing 23, files 16, notifications 12, theming 11, user_status 10, federatedfilesharing 9, user_oidc 9, dashboard 7, federation 7, weather_status 7, dav 6, webhook_listeners 6, files_reminders 3, settings 3, cloud_federation_api 2, oauth2 2, password_policy 2, recommendations 2, updatenotification 2, files_external 1, files_trashbin 1, files_versions 1). Hand-authored: 42 operations (webdav 36, activity 3, serverinfo 3), see below. Total 304: 284 exposed, 20 excluded with a reason each.
- Overlay (`overlay.json`, sha256 in `entry.json`): three query parameters (`shareType` on `GET sharees` and `GET sharees_recommended`, `cursor` on `GET search/providers/{providerId}/search`) carry `nullable: true` next to a `oneOf` with no `type`, which the engine refuses. The overlay replaces those three `parameters` arrays with the same parameters minus `nullable` (marked `x-company-box-supplement`).
- Auth: HTTP Basic, username plus **app password** (Personal settings > Security > Devices & sessions). Use a dedicated service user; an admin app password also reaches the admin operations. Every OCS operation declares the header parameter `OCS-APIRequest` (boolean, default `true`); the engine sends declared header defaults itself, so agents do not pass it. The engine already sends `Accept: application/json`, which OCS answers with JSON. WebDAV answers are XML (207 multistatus) returned as text.
- Health: `ocs-get-capabilities` (`GET /ocs/v2.php/cloud/capabilities`), which also checks the credentials.
- Outward (held for approval, 33): share create/update/resend-email/undelete, federated share from a public link, remote share accept/decline/unshare, all server-to-server share and OCM handlers (`request_handler-*`, 10) and shared-secret requests, admin notifications to users, push register/remove/self-test, user create (welcome mail), resend welcome, wipe user devices, direct download link creation (an unauthenticated file URL), webhook create/update (outbound hooks), ownership transfer, and creating a file comment (visible to others, `@` mentions notify). WebDAV file operations act only inside the user's own storage and are not outward. Email and public-link sharing is one operation (`shareapi-create-share` by `shareType`), so it is held in full.
- Destructive beyond DELETE: wipe user devices, transfer ownership, disable two-factor, disable user, restore a file version (replaces current content). DELETE operations are destructive by rule (users, shares, files and folders to trash, permanent trash delete, empty trash, tags, comments, abort upload, notifications, webhooks, reminders, tasks, status, preferences). Uploads (PUT) and MOVE/COPY with `Overwrite: T` can replace files; the previous content stays as a version when the Versions app is on, so they are writes, not destructive.
- Reads (non-GET, non-mutating): reference extract/resolve (4), translate, notification ID check, password policy validate, share info, search users by phone, device wipe check.
- Excluded (20), each with a reason in `entry.json`: app-password create/rotate/delete/confirm and password confirm (credentials of the connector itself, 5); Login Flow v2 init/poll and OAuth2 authorize/token (credential issuing and browser redirects, 4); app enable/disable (2); `app_config-set-value` and declarative-settings set-value (server and app-wide configuration, 2); user_oidc provider create/update/delete, ID4me and admin config (who can sign in, holds client secrets, 5); federation trusted-server add/remove (2).

## Hand-authored documents (`sources/`, `x-source: hand-authored`, not verified against a live server)

- `webdav.json` (36 operations, written from https://docs.nextcloud.com/server/31/developer_manual/client_apis/WebDAV/ and the server source for system tags): files under `/remote.php/dav/files/{user}/{path}` with `x-multi-segment` paths (PROPFIND with Depth, GET, PUT binary, DELETE, PROPPATCH, MKCOL, MOVE and COPY with `Destination`/`Overwrite`, plus the root folder PROPFIND and REPORT `oc:filter-files` for favorites and tags); chunked upload v2 under `/remote.php/dav/uploads/` (start, list chunks, put chunk, finish, abort); trash bin (list, download, restore, delete, empty); versions (list, download, restore); system tags (list, get, create, update, delete, per-file list, assign, unassign); comments (list, create, update, delete). `Destination` is built from the configured base URL and a template, never a caller URL. Trash and version restores default `Destination` to a fixed name, since the server restores in place.
- `activity.json` (3 operations: stream, filters, stream by filter), from the app's `docs/endpoint-v2.md` at `stable31` (activity 4.0.0; tag `v31.0.14` commit `b16b4bd8760b`).
- `serverinfo.json` (3 operations: info, basicdata, diskdata), from the app README and `routes.php` (serverinfo 3.0.0; tag `v31.0.14` commit `6ea620663b37`). Needs an administrator account.

## Coverage gaps (not in this entry)

- **SEARCH** (WebDAV DASL, `/remote.php/dav` with `d:searchrequest`): the engine has no `x-search` extension (supported keys are propfind, proppatch, mkcol, move, copy, report, lock, unlock). Free-text file search is therefore missing; favorites and tag filters work through the REPORT operation, and `unified_search-search` (OCS) searches by provider.
- **CalDAV and CardDAV**: the Calendar and Contacts apps are not installed on this instance (the `dav` app, which serves the protocols, is enabled), so no calendars or address books are exposed to authoring. Add them if those apps are installed.
- WebDAV bulk upload, LOCK/UNLOCK and public-share WebDAV (`/public.php/dav`) are not authored.
- **Enabled apps with no OpenAPI document** at their pinned tag and no hand-authored spec yet: `app_api` (5.0.2), `circles` (31.0.0, teams), `contactsinteraction`, `files_downloadlimit`, `files_pdfviewer`, `firstrunwizard`, `logreader`, `lookup_server_connector`, `nextcloud_announcements`, `photos` (4.0.0), `privacy`, `profile`, `related_resources`, `richdocuments` (8.7.8), `survey_client`, `text` (5.0.2), `viewer`, `workflowengine`, `bruteforcesettings`, `twofactor_backupcodes`; `support` is a UI-only app. (`activity` and `serverinfo` moved to the hand-authored set.)
- The `comments`, `systemtags` and `sharebymail` OpenAPI documents hold schemas only (0 operations); comments and tags are covered by the hand-authored WebDAV document, email shares by `files_sharing`.
- **Not installed on this instance**, so not covered: Talk (spreed), Tables, Forms, Deck, Notes, Calendar, Contacts, Mail, Collectives. Their specs (Talk 21.1.11 has 154 operations, Tables 79, Forms 27) can be merged by the same script if the apps are installed later.
