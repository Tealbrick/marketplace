# Nextcloud provenance

- App: Nextcloud server 31.0.14 (instance `status.php`: 31.0.14.1, the neuu instance). Captured 2026-10-06.
- Enabled apps were read on the instance with the read-only `occ app:list --output=json`. 49 apps are enabled, 6 are disabled (`admin_audit`, `encryption`, `suspicious_login`, `twofactor_nextcloud_notification`, `twofactor_totp`, `user_ldap`). Disabled apps are not merged (`user_ldap` ships an OpenAPI document, 4 operations, deliberately left out).
- Vendored `openapi.json` is **merged, not edited**: every enabled app's published OpenAPI document merged into one OpenAPI 3.0.3 document (`info.x-source: merged-upstream`), by a deterministic script (apps sorted by name). Per app: component schemas are renamed `<app>.<Name>` and their `$ref`s rewritten; every operation gets `x-nextcloud-app: <app>` and tags `[<app>, <app>/<original tag>...]`, so the Portal group is the app. One `operationId` collided (`preview-get-preview` in core, files_trashbin and files_versions); the later two became `files_trashbin-preview-get-preview` and `files_versions-preview-get-preview`. No path+method collided. sha256 `4349fbf2d3ef93556629af7a44011f0a4cc2cf4d0099e1c6fbf15b91654c4c2e`. The script and build driver are kept in the research workspace (`/Users/puma/work/scratch/nextcloud-merge/`), inputs below.
- Server-bundled sources, `nextcloud/server` tag `v31.0.14` (commit `aec70613fe00fb9bbeec2c5e6726fc3353333ce2`), the `-full` variant where one exists (all scopes), else `openapi.json`: `core/openapi-full.json` (77 ops, sha256 `d9bf66f7eaa0...`), `apps/{cloud_federation_api 2, dashboard 7, dav 6, federatedfilesharing 9, files 16, files_external 1, files_reminders 3, files_sharing 23, files_trashbin 1, files_versions 1, oauth2 2, theming 11, updatenotification 2, user_status 10, weather_status 7, webhook_listeners 6}/openapi.json`, `apps/{federation 7, provisioning_api 43, settings 3}/openapi-full.json`.
- Non-bundled sources (apps shipped with the 31.0.14 release image, installed versions from `occ`), tags `v31.0.14`: `nextcloud/notifications` (installed 4.0.0, `openapi-full.json`, 12 ops, commit `e5370622bb59`), `nextcloud/recommendations` (4.0.0, 2 ops, `c39a2918beab`), `nextcloud/password_policy` (3.0.0, 2 ops, `3a8c9407aa64`); `nextcloud/user_oidc` tag `v8.7.0` (installed 8.7.0, 9 ops, commit `9f13fd44da4e`). Source file sha256 prefixes: notifications `d231fddde522`, password_policy `65e789b3c938`, recommendations `965c3690e4b6`, user_oidc `f4b2db5dc86b`.
- OCS operations: 262 over 24 apps (core 77, provisioning_api 43, files_sharing 23, files 16, notifications 12, theming 11, user_status 10, federatedfilesharing 9, user_oidc 9, dashboard 7, federation 7, weather_status 7, dav 6, webhook_listeners 6, files_reminders 3, settings 3, cloud_federation_api 2, oauth2 2, password_policy 2, recommendations 2, updatenotification 2, files_external 1, files_trashbin 1, files_versions 1). 242 exposed, 20 excluded with a reason each.
- Overlay (`overlay.json`, sha256 in `entry.json`): three query parameters (`shareType` on `GET sharees` and `GET sharees_recommended`, `cursor` on `GET search/providers/{providerId}/search`) carry `nullable: true` next to a `oneOf` with no `type`, which the engine refuses. The overlay replaces those three `parameters` arrays with the same parameters minus `nullable` (marked `x-company-box-supplement`).
- Auth: HTTP Basic, username plus **app password** (Personal settings > Security > Devices & sessions). Use a dedicated service user; an admin app password also reaches the admin operations. Every OCS operation declares the required header parameter `OCS-APIRequest` (boolean, default `true`); the engine has no static or default headers, so the agent must pass `header: {"OCS-APIRequest": true}` on each call. The engine already sends `Accept: application/json`, which OCS answers with JSON.
- Health: `get-status` (`GET /status.php`, public). It proves reachability and the Nextcloud version but **not** the credentials. The intended health check is `ocs-get-capabilities`, which needs the `OCS-APIRequest` header and therefore fails the "no required arguments" rule today (see engine needs).
- Outward (held for approval, 32): share create/update/resend-email/undelete, federated share from a public link, remote share accept/decline/unshare, all server-to-server share and OCM handlers (`request_handler-*`, 10) and shared-secret requests, admin notifications to users, push register/remove/self-test, user create (welcome mail), resend welcome, wipe user devices, direct download link creation (an unauthenticated file URL), webhook create/update (outbound hooks), ownership transfer. Email and public-link sharing is one operation (`shareapi-create-share` by `shareType`), so it is held in full.
- Destructive beyond DELETE: wipe user devices, transfer ownership, disable two-factor, disable user. DELETE operations are destructive by rule (users, shares, notifications, webhooks, reminders, tasks, status, preferences).
- Reads (non-GET, non-mutating): reference extract/resolve (4), translate, notification ID check, password policy validate, share info, search users by phone, device wipe check.
- Excluded (20), each with a reason in `entry.json`: app-password create/rotate/delete/confirm and password confirm (credentials of the connector itself, 5); Login Flow v2 init/poll and OAuth2 authorize/token (credential issuing and browser redirects, 4); app enable/disable (2); `app_config-set-value` and declarative-settings set-value (server and app-wide configuration, 2); user_oidc provider create/update/delete, ID4me and admin config (who can sign in, holds client secrets, 5); federation trusted-server add/remove (2).

## Coverage gaps (not in this entry)

- **WebDAV files layer** (`/remote.php/dav/files/<user>/...`: PROPFIND, GET, PUT, MKCOL, MOVE, COPY, DELETE; trashbin and versions; chunked upload), **CalDAV, CardDAV** (the `dav` app is enabled and serves them), and WebDAV-only features of `comments` and `systemtags` (their OpenAPI documents hold schemas only, 0 operations; `sharebymail` likewise, its shares go through `files_sharing`). Not authored: the engine cannot send them. Two engine changes are required: (1) methods outside `get|put|post|delete|options|head|patch|trace` (PROPFIND, PROPPATCH, MKCOL, MOVE, COPY, REPORT) in the spec parser, `OPENAPI_METHODS`, capability and risk classification, action keys and coverage; (2) a multi-segment path parameter (`{path}` carrying `a/b/c.txt`, encoded per segment, dot segments still refused), because request safety refuses `/` in every path value, so no file below the top folder is addressable. Also needed for MOVE/COPY: the `Destination` header (must stay on the configured origin). XML request bodies, `application/octet-stream` uploads (base64 file object, 25 MB cap) and 207 text responses already work.
- **Enabled apps with no OpenAPI document** at their pinned tag (REST or WebDAV only, so nothing to vendor): `activity` (4.0.0, `/ocs/v2.php/apps/activity/api/v2/activity`), `app_api` (5.0.2), `circles` (31.0.0, teams), `contactsinteraction`, `files_downloadlimit`, `files_pdfviewer`, `firstrunwizard`, `logreader`, `lookup_server_connector`, `nextcloud_announcements`, `photos` (4.0.0), `privacy`, `profile`, `related_resources`, `richdocuments` (8.7.8), `serverinfo` (3.0.0, `/ocs/v2.php/apps/serverinfo/api/v1/info`), `survey_client`, `text` (5.0.2), `viewer`, `workflowengine`, `bruteforcesettings`, `twofactor_backupcodes`. `support` is a UI-only app. Hand-authoring a spec for `activity` and `serverinfo` (small, documented OCS endpoints) is a follow-up.
- **Not installed on this instance**, so not covered: Talk (spreed), Tables, Forms, Deck, Notes, Calendar, Contacts, Mail, Collectives. Their specs (Talk 21.1.11 has 154 operations, Tables 79, Forms 27) can be merged by the same script if the apps are installed later.
- `files_trashbin` and `files_versions` contribute only their preview routes over OpenAPI; list, restore and permanent delete are WebDAV.
