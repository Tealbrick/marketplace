# Documenso provenance

- App: Documenso v2.19.0 (image `documenso/documenso`, released upstream 2026-09-29), deployed on the `neuu` node behind tailscale serve at `https://neuu.<tailnet>.ts.net:8518`. Captured 2026-10-06.
- Source: the instance's own v2 OpenAPI document, `GET /api/v2/openapi.json` (unauthenticated). The v2 spec is generated at runtime by trpc-openapi, so tag `v2.19.0` of github.com/documenso/documenso ships no static v2 file (only the legacy v1 `packages/api/v1/openapi.ts`). The instance serves the deployed version, so it is the exact pin. Vendored byte for byte as `openapi.json`, sha256 `7318cc4d05d22c5034323af61982326fe2166c094db9c0974804b8b623245dfa`. OpenAPI 3.0.3, `info.version` 1.0.0 (not the app version), `servers[0]` = `<host>/api/v2`.
- Operations: 89 (GET 21, POST 68), all exposed, none excluded. The deprecated `/document/*` and `/template/*` operations are exposed next to the `/envelope/*` ones: both families are live in 2.19.0. Exposure: above the 64-operation limit, so `auto` selects discovery.
- Why `openapi` and not the official MCP: the Documenso MCP (`@documenso/sdk-typescript` v0.9.1, MIT, 89 tools) is stdio/legacy SSE only, with no streamable HTTP, and predates 2.19.0 by four weeks. The spec covers the same 89 operations and is served by the instance itself.
- Base path `/api/v2` (set in `entry.json`; the base URL at install is the instance origin).
- Outward (11, held for approval): `distribute` and `redistribute` (envelope and document: send signature requests and reminders by email), `envelope/use` and `template/use` (create from a template and optionally distribute at once), `envelope/cancel` (notifies recipients), `envelope/recipient/{id}/reject` (records a rejection on a recipient's behalf and notifies), `template/direct/create` and `template/direct/toggle` (publish or enable a public direct signing link), `embedding/create-presign-token` (credential for embedded signing or authoring).
- Destructive beyond DELETE: Documenso has no DELETE verb; every removal is `POST .../delete`, so `POST /*/delete` marks all of them (document, envelope, template, folder, recipient, field, attachment, envelope item, direct link) and `envelope/cancel` as admin-capability operations (15).
- Reads (4, `connector.observe`): `envelope/get-many`, `document/get-many`, `template/get-many` (fetch by id list) and `embedding/verify-presign-token` (checks a token, changes nothing).
- Engine note: 58 schemas in the spec use OpenAPI 3.0 `nullable: true` beside `oneOf`/`anyOf` with no `type` (field metadata, reminder settings). Ajv refuses `nullable` without `type`, which made seven create/update/use operations fail to compile, so the engine now rewrites such a schema as `anyOf: [schema, {type: "null"}]` (`openapi-adapter.ts`, covered by a test). The vendored file is untouched and there is no overlay.
- Auth: `Authorization: <token>` with **no** `Bearer` prefix (Team settings > API tokens; a token has full access to its team, no scopes). The `apiKey` security scheme names the same header.
- Health: `GET /folder` (`folder-findFolders`), which needs the token and no arguments.
- Uploads: `envelope/create`, `envelope/use`, `document/create` and friends are multipart (`payload` JSON plus PDF parts), which the engine accepts as file objects.
