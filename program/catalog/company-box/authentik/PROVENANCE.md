# authentik provenance

- App: authentik 2026.2.1 (`ghcr.io/goauthentik/server:2026.2.1`, MIT), deployed on `fed-main` at `https://fed-main.<tailnet>.ts.net:19443`; the live `/api/v3/schema/` reports `info.version` 2026.2.1. Captured 2026-10-06.
- Source: `schema.yml` at tag `version/2026.2.1` of github.com/goauthentik/authentik (sha256 `b2df116d5a5e4e9deb23c5b498f279c8d8f24b880458cc4e92b113c604f95c99`, OpenAPI 3.0.3, `servers: /api/v3`), converted to JSON without any other change (PyYAML `safe_load`, `json.dump` indent 2) as `openapi.json`, sha256 `dced8129a58b9b661f6c87b7d4d1129745c89ff33c34a7ca53d76ee5a94f556d`. The conversion was checked against the schema the instance serves as JSON: every path and component is identical except the multi-tenancy ones below.
- Reconciliation: the tag schema has 1113 operations, the live schema 1099. The 14 extra operations are the six `/tenants/*` paths (`/tenants/tenants/`, `/tenants/domains/` and their members) of the multi-tenancy app, which the deployed instance does not serve. `overlay.json` (a merge patch pinned in `entry.json`, sha256 `1c641526452de5a2d99168a26f823c65702647a2309a4f7b47b3a5b502dd73de`) removes those six paths, so the entry matches the deployed API: 1099 operations (GET 521, POST 169, DELETE 149, PUT 130, PATCH 130). The unreferenced tenant schemas stay in the document.
- Operations: 1099 total, 1091 exposed, 8 excluded. Exposure: discovery (the agent gets search, describe and call tools, not 1091 tools). Base path `/api/v3` comes from the spec.
- Excluded (8), each with its reason in `entry.json`:
  - Code application: `managed_blueprints_apply_create`, and `managed_blueprints_create`, `managed_blueprints_update`, `managed_blueprints_partial_update` (a blueprint's inline content is applied by the server as soon as it is saved: arbitrary model changes and expressions).
  - System tasks: `tasks_schedules_send_create` (runs any schedule now), `tasks_tasks_retry_create` (re-executes any failed task).
  - Credential reveal over a read: `core_tokens_view_key_retrieve` and `endpoints_agents_enrollment_tokens_view_key_retrieve` are GETs that return live keys, so a read grant would reveal credentials.
- Outward (43, held): this is an identity provider, so besides sending, the held class also covers credential-minting and escalation: user recovery link and email, set password, impersonate, token create and set key, service account create, device enrollment tokens; notification transport create, update and test and notification rules; email stage config and the email and SMS authenticator admin enrollments; SCIM, Google Workspace and Microsoft Entra provider create and update and their `sync/object` pushes; Duo automatic device import; flow import; Plex token redemption; flow executor submit; Docker and Kubernetes service connections (container runtime control).
- Destructive beyond DELETE (admin capability; 207 with the 149 DELETEs): group and role membership changes and permission assignment, set password, token set key, impersonate, and everything that stores or runs code: expression policies, every property mapping type (they hold Python expressions) and the policy and property mapping `test` endpoints.
- Reads (3): `POST /admin/system/` (system information), `POST /stages/prompt/prompts/preview/`, `POST /stages/authenticator/duo/{id}/enrollment_status/`.
- Not excluded, by design: creating expression policies and property mappings runs Python inside authentik, so an agent with the admin capability can in effect run code there. Issue the token to a dedicated service account with only the roles the agent needs, never `akadmin`.
- Auth: `Authorization: Bearer <token>` (Directory > Tokens and App passwords, intent API token, bound to a service account; permissions are that user's RBAC).
- Health: `GET /core/users/me/` (`core_users_me_retrieve`), which needs the token.
